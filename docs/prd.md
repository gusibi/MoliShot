# macOS MoliShot PRD

## 产品概述

本产品是一款面向 macOS 的专业截图与录屏工具，目标是在完整覆盖 macOS 原生截图能力的基础上，提供更强的编辑、识别、滚动截屏、固定悬浮、分享与工作流自动化能力。[1][2]

产品定位不是简单“替代系统截图”，而是成为一套覆盖“捕获、编辑、识别、分享、回看、自动化”的完整屏幕信息工作流工具；系统截图负责轻量、即时、零学习成本，本产品负责高频专业使用场景、跨应用信息整理和内容交付。[1][2]

## 产品目标

- 完整支持 macOS 原生截图与录屏核心能力，包括全屏、区域、窗口、延时、录屏、多显示器与高分屏输出。[1][3][2]
- 提供显著优于系统截图的高级能力，包括滚动截图、OCR、固定悬浮截图、尺寸测量、取色、工作流导出与历史管理。[4][5][6]
- 保持“尽可能不打扰被截对象”的系统级体验：截图期间不抢焦点、不强制切换窗口、不破坏当前任务流。[1][7][8]
- 通过高质量交互细节，使截图操作在高频使用下依然快速、稳定、低负担。[6][2]

## 目标用户

### 核心用户

- 产品经理、设计师、开发者、测试工程师，需要高频记录 UI、标注问题、比对界面与输出反馈文档。
- 内容创作者、讲师、博主、客服与销售，需要快速截图、录屏、标注、提取文字并分享链接。
- 普通高频办公用户，需要比系统截图更强的组织、搜索、回看和复用能力。

### 主要使用场景

- 提交 Bug、做设计评审、输出教程、记录会议内容、保存网页长图、从图片中提取文字、跨应用对照参考内容。
- 截取菜单、Popover、Tooltip、视频某一帧、动态图表或短暂状态界面。

## 设计原则

- **不打扰**：默认不冻结屏幕、不抢焦点、不改变窗口状态；冻结模式应作为可选项，而非默认行为。[1][2]
- **一步到位**：截图后立即可复制、标注、固定、分享、OCR、上传，无需在多个应用间跳转。[6]
- **默认好用**：高频操作应零配置即可完成，复杂功能通过渐进披露露出，而不是一开始堆满面板。
- **专业可控**：为专业用户提供完整选项，如颜色空间、输出格式、自动化规则、命名规则、保存策略。
- **系统一致性**：快捷键、窗口行为、焦点机制、视觉反馈尽量遵循 macOS 习惯，减少学习成本。

## 功能模块

## 基础截图模块

### 1. 全屏截图

**功能说明**
- 支持单屏或多屏截图。
- 多显示器场景下，每个显示器可独立输出文件，保持与实际显示像素一致。
- 支持复制到剪贴板、保存到文件、进入编辑器、上传云端等后续动作。

**建议 API**
- `ScreenCaptureKit` 的 `SCScreenshotManager`：用于高性能截图，适合现代 macOS 截图主链路。[1][3][2]
- `SCContentFilter`：用于指定捕获目标，如某个显示器、窗口或内容组合。[7][9]

**为什么使用这些 API**
- `SCScreenshotManager` 是 Apple 面向现代截图场景提供的官方接口，适合做高质量、低延迟、可配置的截图能力。[1][3]
- `SCContentFilter` 能明确指定捕获范围，便于统一支持全屏、窗口和局部场景。[7][9]

### 2. 区域截图

**功能说明**
- 支持十字线框选、自定义拖拽、移动选区、从中心缩放选区。
- 实时显示选区尺寸，建议同时展示 pt 与 px。
- 支持像素级放大镜预览，提高边界选择精度。

**建议 API**
- `SCScreenshotManager` + `SCStreamConfiguration.sourceRect`：用于在确定区域后输出该区域图像。[1][3][10]
- `NSPanel` 或无激活覆盖层窗口：用于绘制截图选择 UI，不抢焦点。[8]

**为什么使用这些 API**
- 截图结果应由系统截图框架生成，而不是自己从屏幕二次采样，前者更保真、更稳定。[1][2]
- 选区 UI 需要始终悬浮且尽量不打断当前窗口焦点，`NSPanel` 更适合作为轻量覆盖层容器。[8]

### 3. 窗口截图

**功能说明**
- 鼠标悬停窗口时高亮候选目标。
- 支持捕获窗口阴影或移除阴影。
- 支持捕获被部分遮挡但仍可共享的窗口。

**建议 API**
- `SCContentFilter`：以窗口为单位指定截图目标。[7][9]
- `NSWindow.SharingType`：识别目标窗口是否允许其他进程访问其内容。[11]

**为什么使用这些 API**
- 窗口截图本质上是对特定窗口内容进行过滤采集，`SCContentFilter` 是天然模型。[7]
- `NSWindow.SharingType` 可帮助识别哪些窗口内容受保护，便于在产品中做失败提示和用户教育。[11]

### 4. 延时截图

**功能说明**
- 支持 3 秒、5 秒、10 秒等常见延时选项。
- 倒计时期间可让用户先展开菜单、Tooltip、Popover 后再截图。

**建议 API**
- `DispatchSourceTimer` / `Timer`：实现延时调度。
- 最终捕获仍用 `SCScreenshotManager`。[1][3]

**为什么使用这些 API**
- 延时本质是调度问题，不需要复杂框架；真正截图仍应走统一捕获链路，保证输出一致性。[1]

### 5. 原生兼容与低版本兼容

**功能说明**
- 在支持的系统上优先使用 `ScreenCaptureKit`。
- 在较老 macOS 上降级到旧接口。

**建议 API**
- `CGWindowListCreateImage`：作为旧系统兼容方案。[12]
- `ScreenCaptureKit`：作为主实现。[2]

**为什么使用这些 API**
- 现代系统优先走新接口可以获得更好的性能和未来兼容性；旧接口仍可用于版本兜底。[12][2]

## 截图交互层模块

### 6. 截图选区 Overlay

**功能说明**
- 截图时显示统一的半透明蒙层、十字线、选区边框、尺寸标尺与放大镜。
- Overlay 不应抢走前台 App 焦点。

**建议 API**
- `NSPanel` / `NSWindow` 非激活浮层。[8]
- `Core Animation` / `CAShapeLayer`：绘制边框、蒙层、准星和动画。

**为什么使用这些 API**
- `NSPanel` 更适合瞬时工具型浮层；`Core Animation` 可在保证性能的同时实现细腻反馈。

### 7. 菜单/Popover 保持打开

**功能说明**
- 用户触发截图时，如果目标应用中的菜单、Popover、Tooltip 已经展开，应尽可能保持当前状态，避免因事件传播而关闭。
- 为了尽量复现系统截图体验，截图会话开始后应断开“物理鼠标移动”和“系统光标位置”的绑定，隐藏真实光标，只保留 Overlay 自己绘制的十字光标与选区反馈。
- Overlay 内部应基于前置拦截到的鼠标事件增量维护一套“虚拟光标”位置，用它驱动 hover、高亮、拖拽和放大镜，而不是继续依赖系统真实指针位置。

**建议 API**
- `CGEventTap`：在更靠前的事件层拦截截图快捷键，避免普通 App 收到该快捷键事件。
- `CGAssociateMouseAndMouseCursorPosition(false)`：在截图会话期间断开物理鼠标和系统光标位置绑定。
- `NSCursor.hide()` / `NSCursor.unhide()`：隐藏真实光标，仅显示 Overlay 绘制的十字光标。
- 不建议仅用 `NSEvent.addGlobalMonitorForEvents` 作为核心实现。

**为什么使用这些 API**
- `CGEventTap` 能在事件进入 AppKit 分发链前处理事件，更接近系统截图行为，因此更有机会实现“菜单保持打开”的体验。[5]
- 仅拦截快捷键或吞掉后续鼠标事件仍然不够，因为很多菜单 hover 与真实系统指针位置绑定；如果真实光标继续移动，底层菜单仍可能变化。断开系统光标绑定并切到 Overlay 自己维护的虚拟光标，才能真正避免“看起来盖住了，但底层菜单还在响应”的问题。
- 如果只在事件分发后监听，很多菜单/Popover 已经因为失焦或外部点击逻辑关闭，效果不稳定。

### 8. 冻结屏幕模式（可选，不默认）

**功能说明**
- 提供“冻结后选区”模式：先截取当前整屏快照，再在静态画面上慢慢选区，适合截视频帧、动态图表、闪烁控件、悬停提示等场景。
- 该能力应作为单独开关，默认关闭，以维持与 macOS 原生一致的“非侵入”体验。

**建议 API**
- `SCScreenshotManager`：先抓取一帧静态屏幕。[1][3]
- `NSPanel` / 全屏覆盖窗口：显示冻结快照并承载后续选区交互。[8]

**为什么使用这些 API**
- 先抓一帧再进行本地选区，是最稳定、最容易控制的冻结方案；同时仍然使用系统截图框架保证图像质量。[1][3]

## 高级能力模块

### 9. 滚动截图

**功能说明**
- 支持网页、文档、长列表等内容的自动滚动拼接。
- 应尽量处理固定头部、悬浮侧栏、懒加载与滚动抖动。

**建议 API**
- `CGEvent`：模拟滚动输入。
- `SCStream`：连续获取滚动过程帧序列。[2][10]
- `Vision` 或自定义图像拼接算法：用于对齐重叠区域。

**为什么使用这些 API**
- 滚动截图不是单张截图，而是“滚动 + 连续捕获 + 拼接”的组合问题，`SCStream` 比单次截图更适合持续取帧。[2][10]

### 10. OCR 文字识别

**功能说明**
- 识别截图中的文字并复制为可编辑文本。
- 支持中英文、多语言、代码、票据或简单表格场景。
- 支持按文字块高亮与点击复制。

**建议 API**
- `Vision` 的 `VNRecognizeTextRequest`：文本识别核心接口。[4][13]
- `VNImageRequestHandler`：对截图图像执行识别请求。[14]

**为什么使用这些 API**
- Vision 是 Apple 官方图像分析框架，支持设备端文本识别，隐私更好、延迟更低、集成成本更低。[4][13]

### 11. 文字框定位与交互复制

**功能说明**
- OCR 后在图上标出文字区域，支持按行、按块甚至按词复制。

**建议 API**
- `VNRecognizedTextObservation.boundingBox`：获取识别区域。
- 坐标转换使用 `VNImageRectForNormalizedRect` 等辅助方法。[15]

**为什么使用这些 API**
- OCR 不应只输出纯文本，定位信息同样重要，它支撑高亮、点击复制、翻译与重新排版等后续体验。[15]

### 12. 固定悬浮截图（Pin）

**功能说明**
- 截图后可将图片固定在屏幕顶层，便于跨应用对照参考。
- 支持缩放、透明度、置顶、鼠标穿透、固定在特定显示器。

**建议 API**
- `NSPanel`：作为不强激活的工具窗口容器。[8]
- `NSWindow.Level`：控制始终置顶层级。

**为什么使用这些 API**
- 固定截图本质上是工具型浮窗，而不是常规文档窗口，`NSPanel` 的行为模型更接近这一需求。[8]

### 13. 取色器

**功能说明**
- 在截图模式中读取任意像素颜色。
- 支持 HEX、RGB、HSL、Display P3、sRGB 等输出格式。

**建议 API**
- 直接读取截图 `CGImage` 像素数据。
- 结合 AppKit 颜色对象做颜色空间转换。

**为什么使用这些 API**
- 直接从截图像素取色能确保所见即所得；颜色空间转换则便于设计与开发协作。

### 14. 尺寸测量 / 间距测量

**功能说明**
- 显示像素宽高、对象间距、对齐参考线。
- 可进一步支持自动吸附到 UI 边界。

**建议 API**
- `Accessibility API`：读取可访问 UI 元素信息。[5]
- 本地图像边缘检测：补足无障碍信息缺失场景。

**为什么使用这些 API**
- 对标准 App 来说，无障碍树往往比纯图像识别更准确；对自绘内容则需要图像检测补充。[5]

## 编辑与标注模块

### 15. 基础标注

**功能说明**
- 支持箭头、矩形、圆形、文字、高亮、序号、画笔、马赛克、模糊。

**建议 API**
- `Core Graphics`：进行静态位图绘制。
- `Core Animation`：负责编辑时的交互预览。

**为什么使用这些 API**
- 标注本质是图像编辑问题，底层 2D 图形能力足够成熟，性能与控制力都更好。

### 16. 撤销 / 重做

**功能说明**
- 编辑器支持完整操作历史。

**建议 API**
- `UndoManager`。

**为什么使用这些 API**
- 这是 AppKit 原生能力，能显著降低编辑器状态管理复杂度。

### 17. 敏感信息打码

**功能说明**
- 自动识别手机号、邮箱、地址、订单号等敏感信息并建议打码。

**建议 API**
- `Vision` OCR + 本地规则引擎。[4][13]

**为什么使用这些 API**
- 先识别文字，再按模式匹配敏感字段，是可解释性和稳定性较好的方案。[4]

## 录屏模块

### 18. 区域录屏与全屏录屏

**功能说明**
- 支持录制单个窗口、区域或整屏。
- 支持录制系统音频与麦克风。

**建议 API**
- `SCStream`：持续获取视频帧与音频流。[2][10]
- `SCContentFilter`：指定录制内容。[7]

**为什么使用这些 API**
- 录屏是持续数据流问题，`SCStream` 是现代 macOS 官方推荐方案，适合高性能视频捕获。[2]

### 19. GIF / 短视频输出

**功能说明**
- 录制结束后可直接导出 GIF 或压缩短视频。

**建议 API**
- `AVAssetWriter`：写入 MP4 / MOV。
- `CGImageDestination`：输出 GIF。

**为什么使用这些 API**
- 视频和 GIF 有不同的编码路径，分别使用成熟的系统编码接口更稳妥。

## 输出、管理与分享模块

### 20. 输出策略

**功能说明**
- 支持保存文件、复制剪贴板、进入编辑器、OCR、固定、上传、分享等可组合动作。

**建议 API**
- `NSPasteboard`：写入剪贴板。
- `FileManager`：保存文件。
- `NSSharingServicePicker`：系统分享面板。

**为什么使用这些 API**
- 这些都是 macOS 原生输出能力，能最大程度保持用户熟悉的系统交互。

### 21. 历史记录与搜索

**功能说明**
- 保存截图历史、支持按时间、OCR 文本、应用名、标签搜索。

**建议 API**
- Core Data 或 SQLite：存储截图元信息。
- Vision OCR 结果索引：支持全文搜索。[4]

**为什么使用这些 API**
- 截图历史是一个典型本地索引问题，需要可靠持久化与高效检索。

### 22. 云端上传与分享链接

**功能说明**
- 自动上传截图并生成可复制链接。

**建议 API**
- `URLSession`：上传文件与请求分享链接。

**为什么使用这些 API**
- 网络上传需求标准，`URLSession` 足够稳定，易于实现重试、进度和后台传输。

## 用户体验规范

## 截图前

- 默认快捷键必须与系统习惯兼容，且允许用户自定义。
- 首次使用时，只在真正触发相关能力时再申请权限，避免首次打开就堆叠多种系统弹窗。
- 所有高频入口应可从菜单栏、快捷键、右键服务、拖拽触发。

## 截图中

- Overlay 不抢焦点，尽量不破坏原窗口状态。
- 十字线、边框、尺寸提示、放大镜必须足够轻量，不能遮住用户正在看的关键内容。
- 对专业用户提供修饰键操作：空格移动选区、Shift 锁比例、Option 中心缩放。
- 菜单、Popover 与 Tooltip 场景应尽可能保留其视觉状态；若无法稳定保留，应在文档中明确说明限制。

## 截图后

- 默认出现浮动预览，但应支持关闭。
- 浮动预览必须支持最短路径操作：复制、标注、固定、删除、分享。
- 默认记住用户最近一次输出策略，但提供“临时覆盖”能力。
- OCR、上传、云链生成等耗时操作应异步，不阻塞用户继续工作。

## 技术与实现注意事项

## 权限

- **屏幕录制权限**：`ScreenCaptureKit` 相关能力依赖用户授权。[2]
- **辅助功能权限**：若要用 `CGEventTap` 拦截全局快捷键或做更深入输入控制，通常需要辅助功能授权。[5]
- **无障碍权限**：若使用 `Accessibility API` 做元素边界识别，也需相关授权。[5]

## 性能

- 截图结果应尽量避免重复压缩和重复色彩空间转换，以免增加延迟与色偏。
- 长截图与录屏必须控制内存峰值，采用分段缓存和渐进拼接，避免大图或长时录制导致内存膨胀。
- OCR 与上传必须异步执行，主线程只负责 UI 响应。

## 兼容性

- 主链路以 `ScreenCaptureKit` 为主；老系统提供兼容路径。[12][2]
- 对受保护窗口、黑屏窗口、DRM 内容、隐私内容必须有明确异常提示，不可静默失败。[11]

## 失败与边界情况

- 菜单/Popover 保持打开不是所有第三方实现都能 100% 复制系统行为，需按输入监听实现方式、权限状态和目标 App 行为综合判断。
- 冻结模式是高级选项，不应强制默认开启，否则会破坏“截图不打扰对象”的主张。
- 滚动截图对网页、Electron、自绘界面、虚拟列表的可靠性不同，需按场景分级支持。

## MVP 范围建议

### 第一阶段（必须）

- 全屏截图、区域截图、窗口截图
- 浮动预览

## 成功指标

- 截图完成到可操作预览出现的时间：尽量控制在 300ms～800ms 内。
- 高频任务最短路径：截图后 1 次点击内完成复制或标注。
- OCR 结果可用率：对常见中英文界面文字达到可接受准确率。
- 历史检索成功率：用户能通过关键词快速找回近期截图。
- 用户留存指标：高频办公用户在一周内形成稳定工作流使用习惯。
